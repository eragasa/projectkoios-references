# Technical debt records

Technical debt records identify implementation structure that is costly,
oversized, difficult to assign to one owner, or otherwise worth bounded future
investigation. A record preserves the observed evidence, unresolved question,
safety constraints, and conditions for considering the debt resolved.

These records are non-authoritative. They do not change repository ownership,
architecture, contracts, public API guarantees, operator policy, or permission
to modify another repository. They do not authorize implementation work or
select a replacement design. An architecture or ownership decision must be made
through its normal authority before a debt record can drive such a change.
